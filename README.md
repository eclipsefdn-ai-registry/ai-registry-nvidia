# AI Registry — NVIDIA (Inferred)

> **Inferred vendor repository.** This repo is maintained by the [AI Registry](https://github.com/eclipsefdn-ai-registry/ai-registry-core) project, not by NVIDIA. It pre-seeds the registry with Agent Skills published by NVIDIA at [github.com/NVIDIA/skills](https://github.com/NVIDIA/skills) and in individual NVIDIA product repositories, plus MCP servers NVIDIA publishes, in the official MCP registry or in its own documentation.
>
> *This entry is based solely on information published through NVIDIA's official public channels. NVIDIA has not endorsed, approved or validated this listing, and is not necessarily participating in the AI Registry.*

## What this repo contains

### Agent Skills

- All skills under `skills/*` in [NVIDIA/skills](https://github.com/NVIDIA/skills) — NVIDIA's own "NVIDIA-Verified" Agent Skills catalog (~330 skills at the time of writing). The repo's README states it is the *"Official, NVIDIA-verified Agent Skills for Claude Code, Codex, and other coding agents"*, sourced from individual NVIDIA product teams (cuOpt, NeMo, DeepStream, DOCA, Jetson, TAO, VSS, and more) and mirrored into this catalog daily via an automated sync pipeline. Every published skill carries a detached cryptographic signature (`skill.oms.sig`) verifiable against NVIDIA's own trust anchor certificate. This one glob covers the large majority of NVIDIA's published skills, including ones that live in per-product repos (e.g. `NVIDIA-AI-IOT/jetson-device-skills`, `NVIDIA/digital-health-skills`, `nvidia-riva/Nemotron-speech-skills`) but are re-published into this catalog once they pass NVIDIA's verification pipeline — approving those source repos separately would create duplicate entries for skills already covered here.
- The NuRec skills, which NVIDIA moved out of the now-deprecated [NVIDIA/nurec-skills](https://github.com/NVIDIA/nurec-skills) into the product repositories they describe (its README names each new location): `nurec`, `physical-ai-datasets` and `physical-ai-av-benchmark` from [NuRec](https://github.com/NVIDIA/NuRec) (still under `io.github.nvidia-nurec`, so `physical-ai-datasets` keeps its id), `asset-harvester` from [asset-harvester](https://github.com/NVIDIA/asset-harvester) (keeping its id `io.github.nvidia-nurec/asset-harvester`) and `harmonizer` from [harmonizer](https://github.com/NVIDIA/harmonizer), which replaces `nurec-fixer`. `nurec-index` became `physical-ai-neural-reconstruction` in the catalog above. `ncore` became `ncore-data-conversion` in [ncore](https://github.com/NVIDIA/ncore), which is not approved: it assumes it runs inside an ncore checkout. Neither is `nurec-onboard`, which is driven by a `run.sh` outside its skill folder.

- Customer-facing skills from individual NVIDIA product repos that the catalog above does not mirror (checked against the catalog's `components.d/` sync list and its skill names), each scoped to the skills actually read and confirmed customer-facing rather than the repo's whole skills directory: [Megatron-LM](https://github.com/NVIDIA/Megatron-LM), [TensorRT](https://github.com/NVIDIA/TensorRT), [TensorRT-LLM](https://github.com/NVIDIA/TensorRT-LLM) (`trtllm-serve-config-guide`), [SkillSpector](https://github.com/NVIDIA/SkillSpector), [OpenShell](https://github.com/NVIDIA/OpenShell) (`skills/*` only), [dgx-spark-playbooks](https://github.com/NVIDIA/dgx-spark-playbooks) (DGX Station skills), [elements](https://github.com/NVIDIA/elements) (the one public `elements` skill), [NeMo-Agent-Toolkit](https://github.com/NVIDIA/NeMo-Agent-Toolkit) (8 of its 11 skills) [OSMO](https://github.com/NVIDIA/OSMO) (`osmo-user`, `osmo-admin`), [cuml](https://github.com/NVIDIA/cuml) (`cuml`), [cudaq-algorithms](https://github.com/NVIDIA/cudaq-algorithms) (`cudaq-algorithms`, whose skill card says evaluation is still pending; the `skills-dev/` maintainer skill is excluded) and [local-ai-inference-recipes](https://github.com/NVIDIA/local-ai-inference-recipes) (`find-recipe`), [cccl](https://github.com/NVIDIA/cccl) (`cccl`), [cuda-python](https://github.com/NVIDIA/cuda-python) (`cuda-python`) and [SkillEvaluator](https://github.com/NVIDIA/SkillEvaluator) (`skillevaluator`).

**Considered and excluded:** repo-internal contributor skills inside product repos (e.g. the `.agents/skills/` trees of `NVIDIA/OpenShell`, `NVIDIA/elements` and `NVIDIA/cuopt`), skills NVIDIA already republishes through the catalog (`NVIDIA/NemoClaw`'s `nemoclaw-user-guide`, and since 2026-10-19 all nine `NVIDIA/nvshmem` skills, approved through the catalog glob instead), and whole-repo skills whose payload would be the entire product repo (`NVIDIA/kubectl-nv`, `NVIDIA/cloudxr-js-samples`). Also `NVIDIA/daqiri`'s `daqiri-onboarding`, considered 2026-11-20: it is customer-facing and signed, but its own documentation map has it locate a DAQIRI checkout and confirm the repository's `CMakeLists.txt`, `docs/` and `scripts/`, and treats the checkout's documentation, generator and validator as the technical sources of truth. The published guides at nvidia.github.io/daqiri are a fallback the file warns may describe a different version, and only concept questions work without a checkout, so the skill does not obtain what it needs the way `nurec` and `harmonizer` do.

### MCP Servers

The first two are listed in the official MCP registry (`registry.modelcontextprotocol.io`), so each approval is just a `serverId` + `date` — consolidation enriches name/description/version automatically:

- **`io.github.NVIDIA/elements`** — NVIDIA Elements, a UI design system and agent-tooling CLI for AI/ML, robotics, and autonomous-vehicle projects (`@nvidia-elements/cli`). Published under the `io.github.NVIDIA` MCP registry namespace, which requires GitHub-org-ownership verification for `github.com/NVIDIA` at publish time, and the linked repository (`github.com/NVIDIA/elements`) is owned directly by the NVIDIA org.
- **`com.nvidia.ngc.nsight.copilot.api/cuda-docs`** — NVIDIA CUDA Docs, a remote MCP server exposing NVIDIA CUDA documentation and code samples to coding agents. Published under the `com.nvidia.*` reverse-domain namespace, which requires proof of `nvidia.com` domain ownership at publish time.
- **`io.github.NVIDIA/kubectl-nv`** — the read-only stdio MCP server built into NVIDIA's `kubectl-nv` GPU-node diagnostics plugin (`kubectl nv mcp`). Not in the MCP registry, so it is self-published with its own `metadata` and `config`, taken from the repo's `docs/agents.md`.
- **`io.github.NVIDIA/multi-storage-client`** — the stdio MCP server built into NVIDIA's Multi-Storage Client CLI (`msc mcp-server start`), self-published with the config from the MSC docs (nvidia.github.io/multi-storage-client).
- **`com.nvidia/nvidia-app`** — the local MCP server built into NVIDIA App for Windows (11.0.9.5xx and later) at `http://127.0.0.1:13508/mcp`, self-published with the config and port fallback documented in NVIDIA's own `nvidia-app` skill (`references/connection.md`).
- **`com.nvidia/rtx-remix-toolkit`** — the local MCP server built into the RTX Remix Toolkit at `http://127.0.0.1:18014/mcp/`, self-published with the config from docs.omniverse.nvidia.com.
- **`com.nvidia/run-ai`** — the MCP server for NVIDIA Run:ai (image `nvcr.io/nvidia/runai/runai-mcp-server`), self-published with the local stdio config from docs.nvidia.com/run-ai (Agents > MCP Server > Connect Your AI Tool). Not in the MCP registry.

**Considered and excluded:** several other MCP registry entries mention "NVIDIA" in their name or description (e.g. `io.github.Yarmoluk/ckg-nvidia-ai`, `io.github.david-eve-za/nvidia-nim-mcp`) but are published by unrelated third-party GitHub accounts, not NVIDIA — excluded as community projects about NVIDIA products, not NVIDIA's own servers. The documentation servers at `docs.nvidia.com/<product>/_mcp/server` (NemoClaw, NeMo Guardrails, Config Manager) are excluded while they answer "MCP requires Ask AI, which is disabled for this docs site".

### Agent Plugins

No Agent Plugin approval is included. The one [agent-plugins.org](https://agent-plugins.org)-conformant plugin NVIDIA publishes, `NVIDIA/skills#plugins/nvidia-skills` (added 2026-10-28), contains only `nvidia-skill-finder`, which the catalog glob above already publishes as `skills/nvidia-skill-finder`; approving the plugin would publish the same skill twice. NVIDIA does have its own separate plugin mechanism for the NeMo Agent Toolkit, but it predates and is unrelated to the agent-plugins.org specification, so it doesn't fit this registry's Agent Plugin artifact type.

### A2A Agents

No A2A agent approval is included: NVIDIA's NeMo Agent Toolkit has first-party support for building and connecting to Agent2Agent (A2A) protocol agents (`nvidia_nat_a2a` package, `docs/source/*/a2a-*.md`), but the concrete artifacts found under that support are toolkit examples (e.g. `examples/A2A/math_assistant_a2a`) rather than a standalone, publicly hosted NVIDIA agent with a real Agent Card — there's no genuinely deployed A2A agent to approve.
